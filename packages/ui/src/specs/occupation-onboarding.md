# 首次引导

## 行为

设置里的「打开引导」和首次进入共用同一套全屏向导，共四步：

1. 工作方向。只写入 `onboardingOccupation` 和本地引导记录，不改变运行时能力。
2. 界面模式。编程或办公。办公模式才会出现主动任务推荐。
3. 助手偏好。工作区记忆、办公模式的主动推荐、以及是否接着打开已有的 Claude 迁移向导。迁移向导继续负责会话、Skills、MCP、命令和 AGENTS.md，这里不再做一遍导入。
4. 可用能力。只介绍模型、代理、技能/插件/MCP、电脑操作和浏览器控制，并可以保存后打开对应的已有设置分区。这一步不写入新的引导答案。

跳过某一页只跳过该页。前三页的跳过仍是显式答案：职业或模式记 `null`，偏好页跳过时记忆和推荐在记录里记 `null`。第四步的「跳过」和「开始使用」都结束向导，不强制打开设置。

「保存并打开」先按当前选择保存，再打开已有分区：

- 模型 → `modelProvider`
- 代理 → `general`（代理在常规设置里）
- 技能、插件和 MCP → `skill`
- 浏览器控制 → `browser`，只在桌面端提供。电脑操作的设置分区是隐藏的，引导只说明输入框按钮默认可用，不跳到该分区。

快捷键、钩子、清理、用量、工作区搜索和自动化不进入这次引导。

## Owner

- 向导步骤和当次选择由 `OccupationOnboarding` 持有。
- 持久化的引导答案仍只有职业、界面模式、记忆和主动推荐。记录格式保持 `onboardingRecord` version 1，不新增字段。
- 设置分区跳转复用 `setPendingSettingsSection` 和 `openSettingsTab`。引导不另存一份「待打开分区」。

## 不变量

- 第四步不能改变引导记录的字段。
- 不打开隐藏的 `computerUse` 设置分区。
- 从设置里再次打开引导时，前三步用该用户最近一次作答预填；第四步没有作答可预填。
